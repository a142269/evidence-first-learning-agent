## 1. 开场

【停顿】同学们好,今天我们来完成【重音】实验 3:用 Python 模拟一个多智能体协作流水线。

这个实验不依赖大模型,【停顿】我们用"伪 LLM"的字符串拼接,模拟 Tutor、Evaluator、Planner 三个 Agent 之间的对话和反思。【停顿】

---

## 2. 黑板模式

【重音】实验采用"黑板模式"——所有 Agent 共享一个全局数据结构(字典),各自读取上面的信息,处理完后写回新结果。

【停顿】这种设计的好处是:Agent 之间不需要"点对点通信",【重音】只需要关心"黑板上现在有什么"。这极大简化了多智能体系统的复杂度。【停顿】

---

## 3. 三 Agent 协作

【停顿】实验设计了三个 Agent:

【重音】Tutor Agent——负责根据主题生成讲解内容,可能"瞎写"。

【重音】Evaluator Agent——负责审核 Tutor 的输出,如果不合格就打回。

【重音】Planner Agent——负责调度,如果连续 3 次审核失败,就降级处理。

【停顿】三者通过黑板 context 字典互相通信,直到输出通过审核或达到最大重试次数。【停顿】

---

## 4. 预期输出

【停顿】运行后你会看到类似这样的输出:

Planner 收到请求 → Tutor 生成内容 → Evaluator 审核 → 审核失败 → 重试 → Tutor 重新生成 → 审核通过 → 推送给学生。

【重音】你会发现:多智能体不是"Agent 越多越好",而是"分工 + 反馈 + 降级"三件套缺一不可。【停顿】

---

## 5. 失败模式

【停顿】实验中你会观察到三种"失败模式":

【重音】目标漂移——Tutor 第二次生成时,主题被改成了"梯度下降",完全跑偏。

【重音】工具误用——Evaluator 想要调用"知识库 API",但参数错了,反复重试。

【重音】超时降级——连续 3 次重试后,Planner 直接放弃并返回"系统繁忙"。

【停顿】这三种失败模式,在真实 A3 系统里都需要专门的兜底逻辑来处理。【停顿】
