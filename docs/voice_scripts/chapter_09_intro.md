## 1. 开场

---

## 2. RAG 是什么

【重音】RAG 的核心思想,只有一句话:【停顿】让大模型在回答问题之前,先从一份可信的知识库里"查资料",然后再"开卷答题"。

这就像一个学生考试——【重音】与其让他凭记忆乱写,不如让他"开卷",但只能看指定的教材。A3 系统的"指定教材",就是课程组的 Markdown 知识库。【停顿】

---

## 3. 完整流程

【停顿】一个标准 RAG 流程,通常包含这几步:

第一步,【重音】文档加载——把课程讲义、参考资料切成小块(chunk)。

第二步,【重音】向量化——用 Embedding 模型,把每块文本变成一个数学向量。

第三步,【重音】索引——把所有向量存入向量数据库,方便后面"按相似度查找"。

第四步,【重音】召回——当学生提问时,把问题也变成向量,从数据库里找出最相似的几块文本。

第五步,【重音】重排序——可选,用更强的模型对召回结果再排一遍。

第六步,【重音】答案生成——把召回的内容塞进 Prompt,让大模型"基于这些内容回答"。

第七步,【停顿】【重音】引用展示——前端把这些内容出处标出来,学生可以一键跳转原文。这就是 A3 系统的"知识库溯源徽章"。【停顿】

---

## 4. 关键参数

【重音】RAG 的效果,取决于几个关键参数。

【停顿】Chunk size 决定每块文本多长。太短,上下文不足;太长,容易引入无关信息。

Overlap 决定块与块之间是否重叠。适当重叠可以避免"恰好把关键信息切断"。

Top-K 决定召回几块。召回太少,信息不全;召回太多,容易让 Prompt 撑爆窗口。

相似度阈值,决定"低于这个分数的召回结果直接丢弃",用来过滤噪声。【停顿】

## 5. A3 中的 RAG

【停顿】在 A3 系统里,RAG 是最核心的"知识保险丝"。【重音】每一道 LLM 生成的讲解,都必须先经过 RAG 检索,引用至少 1 篇课程知识库中的原文。

我们还设计了一种"轻量级 RAG"——【停顿】用 TF-IDF 向量化(而不是大模型 Embedding),这样在 CPU 上也能秒级响应,适合在比赛现场展示。【停顿】
