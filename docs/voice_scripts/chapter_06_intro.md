## 1. 开场

【停顿】同学们好,这一章我们来聊一个非常火的话题——【重音】多智能体系统,Multi-Agent Systems。

如果说上一章讲的大语言模型是一个"超级大脑",那这一章,我们要看看【停顿】怎么让多个大脑组队工作,变成一支高效的"虚拟教师团队"。【停顿】

---

## 2. 为什么需要多 Agent

【重音】为什么不能把所有的任务都塞给一个 AI?原因有三:第一,【停顿】超长 Prompt 会让模型"迷路",丢失中间的指令;第二,【重音】单模型容易"自我说服",缺少监督和反思;第三,【重音】复杂任务需要不同专长,一个通用模型难以面面俱到。

在 A3 系统中,我们设计了一支"虚拟教师团队":【停顿】Planner Agent 负责拆解任务,Tutor Agent 负责讲解,Quiz Agent 负责出题,Evaluator Agent 负责评估,Profile Agent 负责更新学生画像。每个 Agent 各司其职,又通过"黑板"共享上下文。【停顿】

---

## 3. 核心直觉

【停顿】打个比方,【重音】多智能体协作就像医院里的多学科会诊:一个人生了病,先由全科医生分诊,再由专科医生诊断,最后由影像科、检验科提供辅助证据,共同制定治疗方案。

如果只让一个医生从头看到尾,【停顿】一是容易遗漏,二是难以面面俱到。【重音】多智能体系统的精髓,正是"专业分工 + 相互验证"。【停顿】

---

## 4. 常见模式

【重音】多智能体有几种常见的协作模式:

第一种,【停顿】串行流水线——任务像流水线一样,从一个 Agent 传到下一个 Agent,适合"先检索再生成"这样的有序流程。

第二种,【停顿】并行协作——多个 Agent 独立处理同一问题,最后由仲裁者综合结果,适合"多角度评估"。

第三种,【停顿】反思改写——一个 Agent 写完,另一个 Agent 审稿,审完不满意就打回重写,适合"高质量内容生成"。

A3 系统里,我们【重音】混合使用了这三种模式:Planner 串行调度,Tutor 和 Quiz 并行出内容,Evaluator 反馈重写。【停顿】

---

## 5. 失败模式与对策

【停顿】多智能体也有它自己的"坑"。第一种是【重音】目标漂移——Agent 之间互相传话,最后传错了主题。第二种是【重音】工具调用死循环——一个 Agent 反复调用 API 但拿不到结果。第三种是【重音】上下文爆炸——多轮对话后,黑板上的信息越来越多,模型处理不过来。

A3 的对策是:【停顿】每一步都设置超时、设置最大重试次数、对黑板做信息压缩。【重音】记住,多智能体不是"Agent 越多越好",而是"合适就好"。【停顿】
