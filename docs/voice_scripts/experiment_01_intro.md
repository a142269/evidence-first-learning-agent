## 1. 开场

【停顿】同学们好,从这一节开始,我们要亲手"跑一跑"前面章节讲过的技术。今天我们来完成【重音】实验 1:用 Python 实现一个简化版 RAG 检索器。

这个实验的意义在于:【停顿】不依赖任何大模型 Embedding、不需要 GPU、不需要联网,只用 scikit-learn 就能在 5 分钟内看到一个真实可用的检索器。【停顿】

---

## 2. 实验目标

【重音】本实验有三大目标:

第一,【停顿】理解 TF-IDF 是怎么把文本变成向量的——这是所有现代 Embedding 的"祖师爷"。

第二,【重音】理解余弦相似度是怎么衡量"两段文字讲同一件事"的。

第三,【停顿】亲身体验 RAG 检索的"召回过程",看看模型是怎么从一堆文本里挑出最相关的那一条。【停顿】

---

## 3. 核心代码

【停顿】实验的代码只有 30 行,核心三步:

第一步,用 `TfidfVectorizer` 把所有文档和查询一起向量化,确保它们在同一个词表空间里。

第二步,【停顿】用 `cosine_similarity` 算查询向量和每个文档向量的相似度,得到一个长度为 N 的分数数组。

第三步,【重音】取 `argmax` 找出分数最高的那个文档——这就是"Top-1 召回"。

【停顿】然后,把这个文档塞进 Prompt 模板,组装给大模型的"开卷资料"。这就是 RAG 检索的完整流程。【停顿】

---

## 4. 预期输出

【停顿】运行后你会看到类似这样的输出:

系统会打印每个文档的相似度分数,【重音】最高的那一个会被选中,然后被组装成一个标准的"开卷考试"提示词,发送给大模型。

【重音】通过观察分数,你会直观感受到 TF-IDF 的"魔法"——为什么"过拟合"这个词和"训练集表现极好"的文档更相关,而不是和"梯度下降"相关。【停顿】

---

## 5. 常见误区

【停顿】实验中有两个常见误区:

【重音】误区一,认为 TF-IDF 已经过时。【停顿】其实 TF-IDF 在小语料、低算力场景下,效果往往不输大模型 Embedding,比赛现场展示反而更稳。

【重音】误区二,认为 RAG 一定要用大模型 Embedding。【停顿】在 CPU 环境、低带宽环境、对响应时延敏感的场景,TF-IDF + 余弦相似度依然是首选。【停顿】
