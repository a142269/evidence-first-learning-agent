## 三、逐项答辩话术

### 创新点 1 - Multi-Agent Debate

**血缘**：Du et al. "Improving Factuality and Reasoning in Language Models through Multiagent Debate" (NeurIPS 2023)

**我们做了什么**：把 Expert / Critic / Reviewer 三个 Agent 接成 N 轮辩论；Critic 必须给出"事实质疑点 + 改进建议"两段结构化输出；Reviewer 决定是否接受重写或要求第二轮。

**与论文差异**：论文用同质 LLM 互辩，我们做了**角色异质化**——Expert 用高 temperature 探索，Critic 走低 temperature + 引用要求，Reviewer 是仲裁角色。`context.skip_debate=True` 时可绕过（短查询不浪费 token）。

**证据**：`tests/a/test_debate.py`（含 `test_aggregation_picks_primary_skips_meta` / `test_execute_skip_debate` 等用例）+ `tests/a/test_debate_sse_events.py`（4 类事件 × 7 用例）

**30 秒**：
> "我们的资源生成不是 LLM 一次 shot 就交付的——Expert Agent 出初稿，Critic Agent 必须给质疑 + 改进建议，Reviewer Agent 决定是否走第二轮。整个过程通过 SSE 流式让评委实时看到三方角色在打架。这是 Du et al. NeurIPS 2023 的方法，我们做了角色异质化温度策略。"

---

### 创新点 2 - Chain-of-Verification

**血缘**：Dhuliawala et al. "Chain-of-Verification Reduces Hallucination in Large Language Models" (EMNLP 2023)

**我们做了什么**：对资源生成的关键句进行**声明级（claim-level）**抽取 → 对每个 claim 自动生成验证子问题 → 用 RAG/KG 回答 → 不一致就标红回写。

**与论文差异**：论文做的是英文 NLI 数据集，我们落到**教育多模态产物**——PPTX 的每一页、Mermaid 图的每个节点都可以被 claim 化验证。

**证据**：`data/cov_demo_cases.json` 5 个真实案例 + `tests/a/test_cov.py` + `CoVDemoService` 5 维 axes 演示

**30 秒**：
> "CoV 是 Dhuliawala EMNLP 2023 的防幻觉方法——把 LLM 输出拆成 claim、对每个 claim 反问验证、不一致就回写。我们把它落到教育多模态：PPTX 每页、Mermaid 每节点都能被验证。`scripts/verify_demo_assets.py` 一行命令跑完 5 个真实案例。"

### 创新点 3 - Bloom-Aware Reflection

**血缘**：A3 原创（基于 Bloom 1956 的认知层级 × Reflexion (Shinn et al. 2023) 的反思框架）

**我们做了什么**：把 Bloom 6 层（记忆/理解/应用/分析/评价/创造）扩成 **6×3 = 18 子层级**，让反思策略根据 Bloom 层级选择不同的改进维度——比如"应用"层失败给可执行例子，"评价"层失败给多角度论证。

**证据**：`docs/benchmarks/bloom_relabel_audit.md`——**200 题，关键词判别 71% 完全匹配 / 90.5% ±1 层级**，人工抽查 80% 准确

**30 秒**：
> "我们把 Bloom 1956 的 6 层认知扩成 6×3 子层级，让反思策略针对不同认知层走不同改进路径。200 题做了 relabel 审计：90.5% ±1 层级匹配，人工抽 80% 准确——审计报告在 docs/benchmarks/bloom_relabel_audit.md，这是项目里**唯一一份对自家创新点做真实审计**的报告。"

### 创新点 4 - RealDINA 认知诊断

**血缘**：Junker & Sijtsma "Cognitive Assessment Models with Few Assumptions" (Applied Psychological Measurement 2001)

**我们做了什么**：原 DINA 只用了 ~12 个 super-Q 模式简化估计，我们的 **RealDINA 走全量 Q-matrix（20 KP × 200 题）EM 算法 + Platt 校准**——参数维度从 12 提到 220，AUC 从 0.7001 提到 **0.8024**。

**证据**：[benchmark_20260619 reports](reports/benchmark_20260619_153733.md) — RealDINA AUC **0.8024 ± 0.0076**，超论文区间 0.75-0.82 上沿，超 v7 baseline 0.78

**30 秒**：
> "DINA 是经典认知诊断模型，但社区实现普遍简化到 super-Q 模式估计。我们的 RealDINA 跑全量 Q-matrix EM + Platt 校准，AUC 从 0.70 提到 0.80。reports/ 目录的 benchmark JSON 可复现——评委 grep `RealDINA` 就能看到原始 fold 数据。"

### 创新点 5 - SAKT 知识追踪

**血缘**：Pandey & Karypis "A Self-Attentive Model for Knowledge Tracing" (EDM 2019)

**我们做了什么**：实现了 SAKT（自注意力 KT），接入统一 benchmark 入口与 Naive/BKT/DINA/DKT 做完整 5-fold 真实对照。**注意力权重可视化**让评委直接看到"模型在预测这道题时关注学生历史上的哪些题"——DKT 做不到这个可解释性。

**full 5-fold 实测**（ASSISTments-2009 / 3694 学生 / 111 技能 / 336K 交互 / student-wise CV）：

| 模型 | AUC | RMSE | Accuracy |
|------|-----|------|----------|
| Naive | 0.5955 ± 0.0025 | 0.4939 ± 0.0056 | 0.6548 ± 0.0094 |
| BKT | 0.6666 ± 0.0067 | 0.4625 ± 0.0032 | 0.6627 ± 0.0081 |
| DINA | 0.6958 ± 0.0103 | 0.4541 ± 0.0009 | 0.7051 ± 0.0032 |
| DKT | 0.8021 ± 0.0056 | 0.4073 ± 0.0020 | 0.7568 ± 0.0020 |
| **SAKT** | **0.8381 ± 0.0121** | **0.3752 ± 0.0092** | **0.8325 ± 0.0128** |

SAKT 相比 DKT：AUC +0.036 / RMSE -0.032 / Acc +0.076。**五模型里 SAKT 最优**。

**证据**：`reports/benchmark_20260623_201019.{json,md}` (SAKT) + `reports/benchmark_20260623_201927.{json,md}` (DKT) + `reports/benchmark_20260620_210118.json` (Naive/BKT/DINA 历史 full) + `docs/benchmarks/sakt_benchmark.md`

**30 秒**：
> "DKT 是 LSTM、隐状态不可读；我们补了 SAKT（Pandey EDM 2019）做自注意力 KT，按 ASSISTments-2009 student-wise 5-fold 跑了 full benchmark：Naive 0.60 / BKT 0.67 / DINA 0.70 / DKT 0.80 / SAKT 0.84，**SAKT 是五模型里最好的，且不是 smoke，是 full 5-fold 实测**。注意力权重可视化让评委直接看到'模型预测下一题时最关注哪几道历史题'，这是 DKT 做不到的可解释性。"

### 创新点 6 - GraphRAG 2-hop 检索 + HyDE + RRF 三路融合

**血缘**：
- Edge et al. "From Local to Global: A Graph RAG Approach..." (Microsoft Research 2024)
- Gao et al. "Precise Zero-Shot Dense Retrieval without Relevance Labels" (HyDE, arxiv 2212.10496)
- Cormack et al. "Reciprocal Rank Fusion outperforms Condorcet..." (RRF, SIGIR 2009)

**我们做了什么（三件）**：
1. **GraphRAG 2-hop**：从向量库召回 top-k chunk → 沿 KG 边扩 2 跳邻居，让 LLM 看到"概念上下游"
2. **HyDE**：让 LLM 先生成"假设性答案" → 用假设答案的语义去检索，比抽象 query 命中率高
3. **RRF 融合**：把 plain RAG / HyDE / KG 邻居 三路召回用 `1/(60+rank)` 公式融合，自带跨路去重 + score 累加，无需归一化超参

**证据**：
- `services/knowledge_graph/` 100+ 节点 30+ 边
- `services/rag/hyde.py` + `services/rag/rrf.py`
- `tests/a/test_hyde_rrf.py` **12 passed**（HyDE LLM 失败降级 / RRF 跨路累加 / top_n 截断 等）
- `services/rag/__init__.py` 导出 `HydeRetriever / reciprocal_rank_fusion / fuse_with_metadata`

**30 秒**：
> "纯向量 RAG 只看 chunk 的局部相似，会丢掉概念上下游、也容易被抽象 query 卡住。我们做了三件：(1) GraphRAG 2-hop 邻居扩展看上下游；(2) HyDE 让 LLM 先写假设答案再用答案的语义去检索，命中率比原 query 高；(3) RRF 用 `1/(60+rank)` 把三路融合，去重和累加全自动。这三件每件都对应一篇 SIGIR / arxiv 论文，不是工程拼凑。"

### 创新点 7 - 间隔重复三方对照

**血缘**：Wozniak (SM-2, 1990) + Ye (FSRS-4.5, 2023, Anki 默认) + Settles & Meeder (HLR, ACL 2016, Duolingo 学术选择)

**我们做了什么**：三种间隔重复算法**全实现并接入统一调度器**，让项目的复习策略不是拍脑袋规则。

**实测状态（B 6/23 诚实版）**：
- 函数级 smoke 全部跑通（B 真实执行结果）：
  - SM-2: `total_items=50 / due_today=18 / average_easiness=2.41`
  - FSRS-4.5: `total=50 / avg_stability=0.10 / avg_difficulty=1.00`
  - **HLR: `theta=[0.0252, 0.0357, 0.0414] / avg_predicted_recall=0.0254`**（已能拟合参数，不是空壳）
- **day-level MAE / 遗忘率诚实标注"未实测"**——B 在 sm2_fsrs_hlr.md §5 明确解释三个原因：
  1. ASSISTments 原始表没有合适的"下一次复习"day-level timestamp
  2. 仓库缺端到端 scheduler-eval harness
  3. HLR 还差 per-lexeme 特征工程的论文口径
- B 明确不放预期值冒充实测——这是诚信红线

**证据**：`docs/benchmarks/sm2_fsrs_hlr.md` 全文（含 §4 未实测表 + §5 原因解释 + §6 诚实表述边界）+ `backend/app/services/spaced_repetition/{sm2,fsrs,hlr}.py`

**30 秒（B 6/23 推荐诚实版话术）**：
> "我们把 SM-2、FSRS-4.5 和 HLR 三条路线都集成了，并验证到函数级 smoke 输出：SM-2 维护 easiness/interval、FSRS 维护 stability/difficulty、HLR 拟合出 theta 参数。但如果评委追问 day-level MAE 或遗忘率，我会明确说明：当前 ASSISTments 口径缺合适的复习时间戳，我们没把预期值冒充实测。下一步真正需要补的是 scheduler-eval 管线，而不是继续写预期数字。"

### 创新点 11 - Pedagogical Safety / Scaffolding Guard

**血缘**：A3 原创（受 SafeTutors arxiv 2603.17373 + "Rethinking Scaffolding in LLM Tutors" arxiv 2606.15766 启发）

**为什么是教育场景专有创新**：普通 LLM 安全只防 prompt injection / 黄色内容；**AI tutor 真正的危险是教学风险**——直接泄题让学生 copy 不思考、盲目肯定学生错答强化误概念、没有把球抛回学生。

**我们做了什么**：纯规则评估器，**10ms 内**给出 4 字段（无 LLM 依赖，可解释、可测试）：

| 字段 | 范围 | 含义 |
|------|------|------|
| `scaffolding_score` | 0-1 | 分层引导话术命中度（"你觉得" / "想想" / "第一步" 等） |
| `answer_leak_risk` | 0-1 | 直接泄题风险（"正确答案是" / 整段 correct_answer inline） |
| `misconception_reinforcement_risk` | 0-1 | echo 学生错答 + 盲目肯定 + 缺纠错信号 |
| `student_uptake_prompt` | string | 按 Bloom 层级生成的"下一步思考问题"（remember/understand/apply/analyze/evaluate/create 各 2 模板） |
| `overall_risk` | 0-1 | `max(leak, misc) - scaffold/2` 综合 |

**接入位置**：
- `critic_agent` 维度链（`make_critic_dimension()` 工厂，opt-in，不破坏现有 4 维默认）
- `cov_verifier` ContentRewriter 前调用
- `mistake_review / variant_generator` 输出过滤层

**B 解耦**：B 提供"错因 / 当前 Bloom 层级"作为 hint 时评估更精；不传也能跑（mock context 兜底）

**证据**：
- [backend/app/services/pedagogical_safety.py](backend/app/services/pedagogical_safety.py) 280 行
- `tests/a/test_pedagogical_safety.py` **24 passed in 0.48s**（含 critic dimension 适配 × 4）
- 与 critic 联合：`pytest tests/a/test_pedagogical_safety.py tests/a/test_critic.py` **50 passed**，零回归

**30 秒**：
> "评委可能问'AI tutor 是不是会直接给答案让学生不思考'——我们答：我们有 Pedagogical Safety 评估器，给每个 tutor 回复算 4 个分数：分层引导分、答案泄露风险、误概念强化风险、还自动生成把球抛回学生的'下一步思考问题'。整个评估纯规则、10ms 内完成、可解释，对应 SafeTutors 和 Scaffolding 研究方向。"

### 创新点 12 - Claim Ledger / Evidence Trail

**血缘**：A3 原创（受 ARES "Automated Evaluation of RAG Systems" arxiv 2311.09476 启发）

**为什么是教育场景关键创新**：评委追问"AI 怎么避免胡说八道"时，可以直接给出**每句话的证据链**——"CNN 通过卷积核共享权重" → 来源：教材 `ai/04_cnn.md` §L23 + KG 节点 `kp:cnn` + 学生历史错题 `m-12`，置信度 0.92。不是空话，可点击溯源。

**与 CoV (创新点 2) 的关系**：互补不冲突
- **CoV** = 输出**后**验证：抽 claim → 反问 → 不一致回写（防幻觉）
- **Ledger** = 输出**时**打证据：每个 claim 输出时就附来源（可解释性）

**5 种 source type**：
| 类型 | 含义 | 示例 ref |
|------|------|---------|
| `textbook` | 教材章节 | `knowledge_base/ai/04_cnn.md#L23` |
| `kg` | 知识图谱节点/边 | `kp:cnn` |
| `rag_chunk` | RAG 召回 chunk | `chunk-42` |
| `mistake` | 学生历史错题 | `mistake_id:m-12` |
| `history` | 学习历史 / KT 状态 | `path:cnn-2026-06` |

**核心字段**：
- `text`：claim 原文（按句号/分号切句，过滤 < 6 字符）
- `sources[]`：命中的所有 source（含 ref / confidence / excerpt）
- `best_confidence`：最强证据的置信度
- `is_supported`：≥ 0.5 视为有支撑
- `conflict_warning`：同 claim 跨源 confidence 差距 ≥ 0.4 自动标 conflict
- `support_rate`：整段文本的 supported / total 比率

**与 B 解耦**：5 种 source 全 optional，B 提供"学生错题 / 学习历史"时 ledger 自动并入；不提供也能跑（只用 textbook / kg / rag）

**证据**：
- [backend/app/services/claim_ledger.py](backend/app/services/claim_ledger.py) ~280 行
- `tests/a/test_claim_ledger.py` **21 passed in 0.09s**（claim 抽取 / 5 类 source / 子串 + Jaccard 匹配 / 冲突检测 / 统计 / JSON 序列化 / DoS cap）

**30 秒**：
> "评委问'AI 怎么证明自己不是胡说八道'——我们给每句输出自动打 5 类证据：教材章节、知识图谱、RAG chunk、学生错题、学习历史。每条证据有 ref（可点开看原文）、有 confidence（0-1）。一句话被多源支持就高分，被孤立来源支持就标 unsupported，跨源冲突还会自动 conflict warning。这跟 ARES 的 RAG 评估方向是一致的。"

## 四、评委可能追问 · 标准答

### Q1：你们号称 12 创新点，是不是工程堆砌？

→ §3 / §4 / §5 / §8 是**纯数学算法**，跟 LLM 完全无关；§9 是工程原创；§1 / §2 / §6 是论文方法的工程化落地；§11 / §12 是教育场景专有创新（SafeTutors / ARES 启发）。**A3 原创只有 §3 / §9 / §10 / §11 / §12**（5 项），其他都标了论文血缘——我们没有把"工程组装"包装成"学术创新"。

### Q2：哪些数字是实测，哪些是预期？

→ **full 5-fold 实测**：§5 SAKT 0.8381 / DKT 0.8021 / DINA 0.6958 / BKT 0.6666 / Naive 0.5955（同口径 ASSISTments-2009）/ §4 RealDINA AUC 0.8024 / §3 Bloom 90.5% ±1。**诚实标注未实测**：§7 SM-2/FSRS/HLR 的 day-level MAE / 遗忘率（ASSISTments 缺合适的复习时间戳，B 明确不放预期值冒充实测；但 HLR `theta=[0.0252, 0.0357, 0.0414]` 已能拟合）。

### Q3：能复现吗？

→ `git clone` → `cp .env.example .env`（不填 LLM key 也能跑 offline）→ `python -m scripts.verify_demo_assets` → 11/11 通过 + 实际数字打印到终端。

### Q4：跟其他参赛队比，差异化在哪？

→ §3 Bloom 6×3 + 90.5% 审计、§4 RealDINA 全 Q-matrix 0.80 AUC、§9 演示资产健康检查 CLI——**这三件别队大概率没有**。
