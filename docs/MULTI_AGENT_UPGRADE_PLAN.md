# Triple-U 多 Agent 求职项目升级完善计划

## 1. 项目定位、目标与范围

**目标岗位：Agent / 大模型应用开发。周期：6–8 周。**

将 Triple-U 完善为一个能够展示任务规划、受控工具调用、多 Agent 协作、有限纠错、故障恢复和质量评测的学习系统。

旗舰场景固定为：

> “结合课程资料和我的近期错题，讲解这个知识点，出 3 道针对性练习，并给出学习建议。”

简单课程问答继续使用短流程；复杂学习任务进入协作流程。用户实时看到执行进度，内容通过审查后交付。

**两个交付节点：**

- **第 4 周：可演示版本。** 完成可信运行底座、业务工具、多 Agent 协作和前端展示。
- **第 8 周：求职交付版本。** 完成故障演练、检索实验、对照评测、只读 MCP 接入及面试材料。

**复用现有资产：** Vue、FastAPI、LangGraph、PostgreSQL/pgvector、Redis/Celery、Phoenix，以及旧版 Agent、工具注册表、知识图谱、画像和错题服务。

**本轮不做：** 全量迁移旧 Agent、引入 Java 微服务、替换向量数据库、建设独立 MCP Gateway、开放任意代码执行、自动修改画像或发布课程资料。云端模型沿用当前配置，不自动切换到更昂贵的模型。

本计划基于当前代码静态检查；历史评测数字保留原口径，不作为新版本已经达标的证据。

## 2. 分阶段实施内容

### P0｜第 1 周：修复可信度与隔离问题

先建立后续开发可以依赖的运行边界。

- **Run 隔离：** 服务端为每个 Run 创建独立 Graph 线程，`session_id` 仅表示会话。禁止客户端指定检查点身份，避免同会话并发任务串扰。
- **访问控制：** 创建、查询、事件读取、审核、继续执行统一校验身份、课程与 Run 归属。学生只能访问自己的运行；人工审核由有课程管理权限的教师执行。
- **审核语义：** 人审批准的是待交付学习内容，不是授予额外工具权限。删除、发布等未实现操作明确拒绝，不通过审核流程制造“已执行”的假象。
- **运行状态：** 数据库作为权威状态源；进程内字典只作缓存。必要的 Run、检查点持久化失败时，企业协作模式拒绝继续执行；Phoenix 不可用仍可降级。
- **异步与事件：** 同步检索移出事件循环阻塞路径；节点实际执行时发事件，取消 Graph 全部结束后才报告检索完成的行为。
- **检索与评测修正：** RRF 从零累加名次贡献，原始相似度单独保存；严格按有序 Top-5 评分，区分 Hit@5、Recall@5、引用存在率和引用有效性。
- **环境安全：** 增加企业模式配置校验，禁用隐式演示凭据；推送前执行秘密扫描。已泄露凭据的撤销与轮换由账户持有人完成。

**验收：** 并发隔离、越权访问、学生自审、错误脱敏和 RRF 单元测试通过；输出带评测版本号的新基线，旧报告不得覆盖。

### P1｜第 2 周：统一身份、业务语义和工具执行

**身份与课程权限**

复用现有注册账号和登录响应，补充持久化会话、学生选课关系及教师授课关系。会话凭据在数据库中仅保存摘要，支持过期、登出撤销和服务重启。

沿用现有学生／教师角色体系，不新增复杂组织架构；演示账号和课程关系通过显式种子数据创建。现有密码存储升级为带盐的专用密码哈希，历史账号在成功登录后迁移。独立 OIDC 平台留待后续。

**轻量学习语义层**

先统一四类信息：

| 信息 | 必须携带的业务解释 |
|---|---|
| 近期正确率 | 时间窗口、样本量、题目范围 |
| BKT 掌握概率 | 知识点、模型来源、更新时间 |
| 薄弱知识点 | 判定规则、支持记录、数据充分性 |
| 学习目标与先修关系 | 来源、知识点标识、适用课程 |

计算由服务完成，Agent 负责解释。缺失值明确表示未知，不将“没有记录”解释为“掌握度为零”。

**扩展现有工具注册表**

新增或适配四个只读业务工具：

- `search_course_evidence`
- `get_learning_profile`
- `get_recent_mistakes`
- `get_prerequisites`

统一参数校验、返回结构、版本、权限、超时、重试分类和调用审计。身份由服务端注入，模型不能通过参数切换到其他学生。

工具返回状态区分成功、无数据和执行失败；不能把异常包装成普通答案后继续生成。画像与错题默认读取当前学生，近期窗口默认 30 天。

**验收：** 工具可独立测试；非法参数、跨课程调用、伪造学生身份均被拦截；统计结果能追溯到支持记录。

### P2｜第 3–4 周：完成多 Agent 旗舰闭环

采用集中编排，角色之间通过结构化状态传递结果，不建立自由相互调用网络。

| 角色 | 职责与输出 |
|---|---|
| Planner | 读取必要学习状态，选择交付物、知识点和检索任务，输出受约束计划 |
| Tutor | 基于证据生成讲解，输出段落、事实声明和引用标识 |
| Practice | 复用出题、学习路径能力，输出练习、答案解析和学习建议 |
| Reviewer | 结合原始证据独立检查事实、题目答案及目标覆盖，输出具体修订要求 |

执行流程：

**鉴权与安全检查 → 路由 → Planner 与工具读取 → 证据检索 → Tutor / Practice 并行 → Reviewer → 必要时补检索及定向修订 → 交付。**

固定行为：

- 默认仍走普通问答；用户选择“协作学习”进入旗舰模式。自动路由作为独立实验，不决定首版可用性。
- Planner 只能使用预定义任务模板和工具，不能生成任意执行代码。
- Tutor 与 Practice 使用同一证据快照和学习摘要，结果分别存储。
- Reviewer 保留规则校验，并增加独立模型审查；审查意见必须指向具体段落或题目。
- 每个 Run 最多补检索一次、修订一轮，之后必须结束。
- 无证据则说明不足；画像缺失则提供通用建议；未通过检查的内容不交付。
- 核心讲解不合格时整体失败；练习或建议不合格时允许部分完成，但必须列出缺失部分。
- 旧 Agent 的下载文件注册、画像写入等副作用从 V2 生成阶段剥离，避免生成过程意外修改业务数据。

**Harness 默认上限：**

- 两个生成 Agent 并行；
- 每 Run 最多 12 次模型调用、16 次工具调用；
- 活动执行时间 120 秒，不包含人工等待；
- 模型累计输出额度 16,000 tokens，输入上下文同时受单次调用上限约束；
- 重试、修订和恢复继续消耗同一 Run 预算，不能重新获得额度。

预算在调用前预留，并行操作原子扣减。真实用量与估算用量分别标记；已发送但结果不明的请求不能直接视为零成本。

**前端交付：** 复用聊天和 Trace 组件，展示任务进度、来源片段、练习卡片、建议与修订摘要，不展示内部推理全文。学生只能看到审核通过的内容。

**验收：** 完整演示正常交付、缺画像、缺证据、Reviewer 发现错误并修正、达到预算上限五类场景。

### P3｜第 5 周：故障恢复、幂等与异步摄取可靠性

**运行恢复**

- 每个 Run 保存工作流版本、检查点、预算计数和执行租约。
- 通过数据库条件更新取得执行权；过期执行者不得继续提交状态。
- 浏览器断线触发取消请求，停止调度新步骤；已在途调用可能仍有费用，状态明确显示为中断。
- 提供显式“继续执行”，从最后完成的检查点恢复。服务启动时识别失效租约，不自动重复启动全部任务。
- 人审等待保持独立状态，继续执行接口不能绕过审批。
- 已完成的 Agent 输出可复用；尚未持久化的模型调用允许重算，明确不承诺外部调用恰好一次。

**摄取幂等与文档版本**

- 上传时创建持久化摄取任务，任务标识贯穿解析、审核、向量化和激活。
- 相同任务重投返回已有进度或结果，不创建新逻辑文档。
- 替换资料必须显式关联已有文档；相同内容返回未变化，不同内容创建新版本。
- 新版本完整就绪后再切换活动版本，旧版本保留用于审计。
- Chunk 使用版本与块序号等稳定身份，数据库唯一约束防止重复写入。
- 企业摄取状态与兼容索引同步状态分别记录，避免只完成一条路径却显示全面成功。

**验收：** Worker 在写库后、确认任务前退出；重复上传请求；重复审批；后端重启；模型超时；检查点不可用。每种故障都有固定脚本、预期状态和恢复证据。

### P4｜第 6 周：检索诊断与质量实验

首先记录稠密召回、词法召回、融合、去重和最终上下文各阶段结果，定位现有失败样本。

本轮完成三组可复现实验：

1. 仅稠密检索；
2. 修正后的混合检索与 RRF；
3. 混合检索加片段多样性策略：去除完全重复片段，同一来源最多保留两个互补片段。

保持语料、模型、测试集和 Top-K 一致，并统计候选召回、最终排序、答案支撑和延迟。文档分块记录标题、章节、块位置及版本；对完整定义被切断等失败单独建立回归样本。

新策略只有在开发集质量提高、延迟增幅不超过 20%，且固定回归集无安全退化时才替换默认策略。

**本轮不预先承诺接入新的 Reranker 或更换 Embedding。** 交付检索瓶颈报告；若正确证据未进入候选集，优先修复入库、过滤或召回。中文重排模型选型留作明确的后续实验，避免无依据扩大范围。

### P5｜第 7 周：只读 MCP 扩展

内部工具层验收后，以独立适配器暴露以下能力：

- 课程证据检索；
- 知识点先修关系查询；
- 当前用户学习摘要读取。

采用官方 Python MCP SDK 的本地 stdio 接入，固定依赖版本，不搭建独立网关。适配器调用现有受控后端工具入口，不直接访问数据库。

凭据通过环境注入；工具列表依据权限过滤，执行时再次鉴权。首版不暴露写操作、代码执行或其他学生画像。

**验收：** 一个本地 MCP 测试客户端完成发现和调用；过期凭据、越权调用及后端超时都有测试；同一操作可在业务 Run 和工具审计中关联。

### P6｜第 8 周：发布验收与求职交付

- 完成端到端验收、对照实验和固定留出集人工审查。
- 更新 README、架构说明、ADR、演示脚本和求职材料，明确已实现、实验性与未实现能力。
- 录制 5 分钟正常流程，以及独立的故障恢复演示。
- 准备项目讲解和追问题库，以代码、失败案例、测试和报告支撑回答。
- 不将本地测试描述为真实生产规模，不虚构用户量、调用量或性能收益。

## 3. 接口、数据与兼容约定

**公共 API**

继续使用 `/api/v2/learning-runs`：

- 创建请求增加 `workflow=qa|learning_package`，默认 `qa`；协作模式增加交付物选择和题量，默认 3 道，范围 1–5。
- 保留现有查询和审核恢复接口，补充经过鉴权的事件查询、取消与继续执行接口。
- 审核恢复仅处理人工决定；继续执行仅处理可恢复中断，两者权限与状态检查分离。
- 创建运行与上传接口支持幂等键；同键同请求返回原任务，同键不同请求返回冲突。

**事件与结果**

保留原 SSE 名称，新增任务计划、Agent 开始／结束、工具调用、审查和修订事件。事件具有持久化顺序号；重连补读不会创建新运行。

最终结果保留原有答案、引用和证据字段，新增学习包、各部分状态、审查摘要、修订次数、用量及分阶段耗时。终态区分完整成功、部分完成、失败、拒绝和取消。

**内部契约与存储**

新增结构化任务计划、学习数据快照、证据片段、学习包、审查意见和工具结果契约；保留旧 Agent 接口，通过适配层接入。

增量迁移涵盖：

- 持久化会话、课程授权；
- Run 工作流版本、执行租约和预算；
- Run 事件、工具执行记录和必要快照；
- 摄取任务、活动文档版本及唯一约束。

授权、业务数据访问和 V1 降级路径必须使用同一课程范围；降级不能扩大权限。原始凭据不进入日志，学习快照最小化保存并受 Run 权限保护。

V1 保持可用。新能力通过开关开放，关闭后停止创建新协作任务；兼容版本仍可处理已存在的审核任务。带未完成任务的工作流不得直接删除。

## 4. 测试、评测与发布门槛

**测试分层**

| 层级 | 必须验证 |
|---|---|
| 单元与契约 | 路由、工具参数、业务统计、预算、RRF、引用映射、指标计算 |
| 数据库集成 | 身份课程隔离、Run 租约、并发审批、版本激活、摄取幂等 |
| 工作流 | 补检索、有限修订、部分完成、无证据、模型结构错误 |
| 故障恢复 | 进程退出、重复任务、服务超时、断线、检查点失效 |
| 前端端到端 | 真实进度、来源展开、练习交互、审核拒绝、继续执行 |
| 兼容回归 | V1 问答、上传、已有 Agent 和离线演示 |

**评测集与指标**

保留原 66 条用例及历史结果；修正指标或安全语义时记录版本和理由，不删除失败安全样本换取通过。

新增 24 条协作用例，按正常任务、证据与纠错、边界与失败三类各 8 条；每类一半用于开发，一半固定留出。额外的并发、重试和权限测试独立于这 24 条统计。

分别报告：

- 来源 Hit@5、Recall@5；
- 引用存在率、引用有效性、事实支撑率；
- 完整任务成功率与部分完成率；
- 练习答案正确性、修订成功率；
- 工具执行成功率与语义正确率；
- 人工审核触发率与异常接管率；
- P50/P95 活动耗时、人工等待、模型调用数及成本。

模型评审作为辅助，固定留出集由人工按预先确定的标准盲审。

**消融实验**

同一批任务比较：单 Agent、分工无 Reviewer、完整协作闭环。固定模型、语料和预算上限，保留实际消耗与逐例结果。不得预先承诺协作一定优于单 Agent。

**发布门槛**

- 权限、身份隔离、引用标识有效性、预算限制及幂等测试全部通过。
- 修正口径后的来源 Hit@5 ≥ 85%，且较同口径基线下降不超过 3 个百分点。
- 固定协作留出集至少 11/12 完整成功；人工审查的事实支撑率 ≥ 90%；不得存在未修复的严重事实错误或明显错误答案。
- 超时任务必须正确终止或中断，不能挂起不收敛。
- 对照实验未证明质量收益时，保留协作入口但不自动推广，也不在简历宣称收益。

PR CI 运行离线测试、迁移和契约检查；受控发布流程运行真实模型评测并保存报告。性能测试固定环境、并发和请求数，不用模拟模型延迟宣称真实线上性能。

## 5. 最终交付与执行原则

最终应具备以下可审查成果：

1. 一条完整的协作学习链路和保留的普通问答短路径。
2. 一套实际生效的权限、预算、工具与状态恢复机制。
3. 一组重复投递、崩溃恢复和越权防护的故障演练。
4. 一份版本化评测报告、检索诊断报告和多 Agent 对照实验。
5. 一个复用内部治理能力的只读 MCP 适配器。
6. README、ADR、5 分钟演示、简历项目描述、STAR 故事与面试追问题库。

每项核心设计均配套：**业务问题、关键实现、失败案例、验证结果**。面试准备另外覆盖 Python 异步与阻塞、数据库索引、任务队列、LRU＋TTL、堆与 DAG 调度，不为覆盖题目而增加系统组件。

周数是单人持续投入下的里程碑安排，不是质量保证。阶段按验收结果推进；如果延期，优先保证第 4 周核心闭环和可靠性，MCP 与检索实验顺延，不以跳过安全和评测换取表面完成。

本轮交付的是升级计划；实施时先完成 P0，再按依赖顺序推进，不将计划中的能力写成已完成成果。
