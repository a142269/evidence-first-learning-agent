# 结构化输出稳定性：诊断与复测（2026-10-18）

> 本记录是对 `evals/results/retry-development-20261017.md` 中“仍有结构化输出失败”的后续诊断与修复复测。原始实验记录保持不变；本文件只补充新证据。所有模型调用为 DeepSeek Flash（`deepseek-flash`），使用冻结证据，**未进行人工质量评分**。原始响应与逐调用记录只保存在本地 Git 忽略目录（`output/stability-20261018/`），未提交、未上传。

## 1. 诊断结论

对 2026-10-17 开发集复测中失败的 3 个任务（`ab-006`、`ab-011`、`ab-012`）用同一配置（无 Reviewer 臂，每次调用最多 1024 output tokens，最多 8 次模型调用）做了一次 13 次调用的诊断：

- 6/6 次失败的 Practice 调用与 1 次 Tutor 调用都在 **恰好 1024 output tokens** 处停止，返回的 JSON 未闭合；
- Planner 调用 0/3 截断；
- 因此失败机制是**输出长度截断**，不是字段类型错误、拒答或服务商错误；
- 当时的解析/重试逻辑无法区分截断与普通格式错误：只接受纯 JSON（仅剥离精确的 ```json 围栏）、丢弃 `finish_reason`、重试提示只要求“闭合括号”，不会要求缩短输出，所以第二次仍然截断。

该诊断证明的是“这 3 个开发集样本在 1024 tokens/调配置下的失败原因”；生产默认是 2048 tokens/调，不能把该配置下的失败率直接当作生产失败率。

## 2. 修复（`learning-package-v2.8`）

1. `LLMClient.achat_strict_with_usage` 返回 `finish_reason`（无值时为 `null`），不改变任何既有字段。
2. JSON 解析容忍 Markdown 围栏与 JSON 前后的说明文字；仍按 Pydantic Schema 严格校验，不放宽任何字段约束。
3. 识别截断（`finish_reason == "length"` 或 JSON 未闭合）后追加一次**固定文案**的精简要求（不回显模型输出）：明确各字段的字数上限；截断场景最多 3 次尝试，普通无效输出仍为 2 次；所有尝试计入既有模型调用/输入字符预算。
4. 消融执行器把“仅讲解、无练习”的降级结果标记为**未完成完整任务**（`learning_package_incomplete_package`），不再把可选的部分交付计为完整成功；完整学习包仍正常计数。
5. 回归测试：`tests/a/test_structured_output_robustness.py`（9 项，离线、无模型调用），覆盖围栏/前后说明解析、截断识别、3 次上限、普通错误仍 2 次、`finish_reason` 暴露、消融完整性语义。

## 4. 不能据此得出的结论

- 这是**每个任务一次**的运行，模型输出有随机性；没有方差估计，不能声称提升具有统计显著性。
- 本次同时包含 v2.7 部分交付语义、v2.8 截断重试/解析容忍和消融完整性修正；**不能把提升单独归因**给某一个改动。
- 留出集任务在此前消融实验中已被模型执行过；本次不是全新的未使用任务集。真正的独立任务与人工评分仍待安排。
- 完整任务数只说明“生成了符合契约的完整学习包”，**不证明讲解正确、题目答案正确、事实受证据支持或质量优于其他方案**。人工逐 claim 与练习评分仍未完成。
- 实验配置为 1024 tokens/调（历史公平性设置），生产默认 2048；两者不能直接换算失败率。
