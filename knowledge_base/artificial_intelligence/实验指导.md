## 实验1：简化版 RAG (检索增强生成) 检索机制

### 1. 实验目标
- 从零实现文本的词袋向量化（Bag of Words）及 TF-IDF 权重计算。
- 掌握余弦相似度（Cosine Similarity）的底层数学计算过程及其在文本检索中的物理意义。
- 深刻理解 A3 项目中“知识库溯源”和“课程片段提取”的底层工作流，即便在不依赖任何大型专用向量数据库（如 Chroma、Pinecone）或复杂的深度学习 Embedding 模型的情况下，也能快速搭建高可用检索器。

### 2. 实验背景与核心原理
**检索增强生成 (Retrieval-Augmented Generation, RAG)** 是解决大语言模型“幻觉（Hallucination）”和“知识更新滞后”最有效的工业级方案。RAG 的核心分为“检索 (Retrieval)”和“生成 (Generation)”两步。
本实验聚焦于“检索”环节。我们将使用经典的 **TF-IDF (词频-逆文档频率)** 算法将课程讲义文本转换为数学向量。TF-IDF 的精妙之处在于：它不仅统计了一个词在当前段落中出现的频率（TF），还会严厉惩罚那些在所有段落中都广泛出现的“水词”（如“的”、“是”、“了”），从而精准抓取能够代表文本核心语义的特征词。

### 3. 可运行代码示例
本实验使用 `scikit-learn` 中的 `TfidfVectorizer`，将几段简短的课程材料向量化，然后根据用户提问，计算余弦相似度并召回最相关的一段文本，最后组装给 LLM 的提示词。

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

# 1. 准备 A3 课程知识库的文档切片 (Chunks)
# 在真实的 A3 系统中，这些 chunk 来源于经过 Markdown 标题切分后的知识库文件
documents = [
    "Transformer 模型完全抛弃了 RNN，使用了 Self-Attention 机制来实现并行计算，极大提升了训练速度。",
    "过拟合是指模型在训练集上表现极好，但在没见过的测试集上表现很差。可通过正则化或早停法缓解。",
    "多智能体系统 (Multi-Agent) 是由多个专门角色的 Agent 组成的网络，比如 A3 系统中的 Planner 和 Tutor 相互协作。",
    "检索增强生成 (RAG) 结合了向量检索和 LLM 的生成能力，能有效缓解大模型的幻觉，提供可溯源的解答。"
]

def simplified_rag_retrieval(query, docs, threshold=0.1):
    """简化的 RAG 检索器"""
    print(f"\n=============================================")
    print(f"【用户提问】: {query}")
    print(f"=============================================")
    
    # 2. 将文档和查询合并，共同进行 TF-IDF 向量化
    # 这一步是为了确保查询词和文档词在同一个向量空间 (Vocabulary) 中
    vectorizer = TfidfVectorizer()
    all_text = docs + [query]
    tfidf_matrix = vectorizer.fit_transform(all_text)
    
    # 3. 分离出文档向量 (前 N 行) 和查询向量 (最后 1 行)
    doc_vectors = tfidf_matrix[:-1]
    query_vector = tfidf_matrix[-1]
    
    # 4. 计算查询向量与所有文档向量的余弦相似度
    # 结果是一个包含 N 个相似度得分的数组，值域为 [0, 1]
    similarities = cosine_similarity(query_vector, doc_vectors).flatten()
    
    # 5. 找到相似度最高的文档索引 (Top-1 召回)
    best_idx = np.argmax(similarities)
    best_score = similarities[best_idx]
    
    print("\n[ 系统内部检索日志 ]")
    for i, score in enumerate(similarities):
        print(f"  -> 与 Chunk {i+1} 的相似度: {score:.4f}")
    
    print("\n【最终检索与增强结果】")
    if best_score >= threshold:
        print(f"✅ 成功召回最相关文档 (最高相似度 {best_score:.4f}):\n   \"{docs[best_idx]}\"")
        print("-" * 50)
        print("【LLM 提示词组装 (Prompt Formulation)】")
        prompt = (
            "你是一个严谨的 AI 助教。请严格基于以下已知信息回答学生的问题。\n"
            "如果已知信息无法回答问题，请直接回答“知识库中未找到相关内容”。\n\n"
            f"[已知信息]：{docs[best_idx]}\n\n"
            f"[学生问题]：{query}\n\n"
            "[你的解答]："
        )
        print(prompt)
    else:
        print(f"❌ 检索失败：最高相似度 {best_score:.4f} 低于阈值 {threshold}。")
        print("💡 系统阻断响应，拒绝回答以防模型产生事实性幻觉。")

if __name__ == "__main__":
    # 场景 1：精确语义命中（有明显关键词交集）
    simplified_rag_retrieval("请问 Transformer 是用什么机制替代了 RNN 算法？", documents)
    
    # 场景 2：跨领域无关提问，触发防幻觉阈值阻断
    simplified_rag_retrieval("如何做一盘正宗的鱼香肉丝？", documents)
```

### 5. 常见误区与避坑指南
- **误区 1：** RAG 就是把整本书的所有文字一次性复制粘贴，全部塞进 ChatGPT 的对话框里。
  - **避坑：** 大模型的上下文窗口是有限且极其昂贵的，过长的文本不仅会拖慢响应速度，还会导致模型“注意力涣散”（Lost in the middle 现象）。RAG 的核心工程难点在于**精确切块与召回 (Retrieval)**，只提取最相关的 Top-K 个切片（Chunk）作为上下文。
- **误区 2：** 只要检索到了内容，大模型的回答就一定 100% 正确。
  - **避坑：** 即使使用了 RAG，LLM 依然有可能对检索到的文本进行错误总结。因此，强大的 RAG 系统不仅需要 Prompt 约束，还需要在前端提供“引用溯源（Citations）”，让用户可以直接点击链接查看原始 Markdown 讲义。

### 6. 拓展思考题
1. TF-IDF 是一种基于“词频统计”的字面匹配方法。如果用户搜“深度学习的爆发”，而知识库文档里写的是“多层神经网络的崛起”，TF-IDF 能搜出来吗？为什么现代工业级 RAG（如 A3 系统的底层）通常倾向于使用深度学习 Embedding 模型（如 `text-embedding-3-small` 或 `BGE-M3`）来替代纯字面的 TF-IDF？
2. 试想如果我们将 `threshold` 设置为 0.9，在这个实验中会发生什么？阈值的设定在“防幻觉（高精确率）”和“有问必答（高召回率）”之间应该如何权衡？

## 实验2：学习掌握度追踪 (BKT 贝叶斯知识追踪直觉演示)

### 1. 实验目标
- 深刻理解自适应教育系统背后的王牌算法：贝叶斯知识追踪（Bayesian Knowledge Tracing, BKT）的核心思想。
- 使用纯 Python 实现一个简易的后验概率更新算法。
- 模拟并可视化 A3 项目中 `Profile Agent` 如何在后台默默动态跟踪学生对某一个知识点（如“反向传播”）的掌握概率，为下一阶段的个性化路径规划提供数据支撑。

### 2. 实验背景与核心原理
在个性化教育系统中，最核心的问题是：**“我怎么知道这个学生到底有没有学会？”**
传统的计分法（做对+1分，做错-1分）非常粗糙。真实世界中存在大量干扰因素：
- **猜测 (Guessing)**：学生其实根本不懂这个知识点，但这是一道选择题，他有 25% 的概率蒙对。
- **失误 (Slipping)**：学生已经完全掌握了知识点，但他因为粗心算错了一个小数点，导致这道题做错了。

贝叶斯知识追踪正是为了过滤这些噪声而生的。每次学生提交答案后，系统都会利用贝叶斯定理更新一个概率分布：在考虑到“蒙对”和“粗心”概率的前提下，学生**真实掌握该知识点**的置信度到底是多少。

### 3. 可运行代码示例

```python
def update_mastery_probability(prior_prob, is_correct, p_guess=0.2, p_slip=0.1):
    """
    基于贝叶斯定理的知识掌握度追踪 (简化版 BKT 更新逻辑)
    
    :param prior_prob: 答题前，系统认为学生已掌握该知识点的先验概率 P(L)
    :param is_correct: 本次答题是否正确 (True/False)
    :param p_guess: 猜测概率 P(Correct|~L) (没掌握但蒙对的概率，通常选择题约为 0.2-0.25)
    :param p_slip: 失误概率 P(Wrong|L) (真掌握了但粗心做错的概率，通常约为 0.1)
    :return: 答题后更新的后验掌握概率 P(L|Correct) 或 P(L|Wrong)
    """
    if is_correct:
        # 学生做对了：
        # 分子: 他真掌握了且没失误的联合概率 ( P(L) * P(Correct|L) )
        prob_correct_given_mastered = 1 - p_slip
        numerator = prior_prob * prob_correct_given_mastered
        
        # 分母 (全概率公式): 他做对的总概率 = 掌握且没失误 + 没掌握但蒙对了
        prob_correct_given_not_mastered = p_guess
        denominator = numerator + (1 - prior_prob) * prob_correct_given_not_mastered
    else:
        # 学生做错了：
        # 分子: 他真掌握了但失误了的联合概率 ( P(L) * P(Wrong|L) )
        prob_wrong_given_mastered = p_slip
        numerator = prior_prob * prob_wrong_given_mastered
        
        # 分母 (全概率公式): 他做错的总概率 = 掌握但失误 + 没掌握且没蒙对
        prob_wrong_given_not_mastered = 1 - p_guess
        denominator = numerator + (1 - prior_prob) * prob_wrong_given_not_mastered
        
    return numerator / denominator

def simulate_student_journey(student_name, initial_prob, responses):
    """模拟一个学生完整的做题旅程，并实时打印画像更新过程"""
    current_mastery = initial_prob
    print(f"\n👤 建立学生档案：[{student_name}] | 初始知识点掌握度评估: {current_mastery*100:.1f}%")
    print("-" * 50)
    
    for i, response in enumerate(responses, 1):
        is_corr = response["is_correct"]
        action_text = "✅ 答对" if is_corr else "❌ 答错"
        
        # 执行核心贝叶斯更新
        new_mastery = update_mastery_probability(current_mastery, is_corr, p_guess=0.25, p_slip=0.1)
        
        print(f"第 {i} 题提交: {action_text}  -->  内部掌握度置信度从 {current_mastery*100:.1f}% 更新为: {new_mastery*100:.1f}%")
        current_mastery = new_mastery
        
    print("-" * 50)
    if current_mastery >= 0.85:
        print(f"🎯 【A3 决策引擎】：已确认 [{student_name}] 掌握该节点！自动解锁下一高级章节。")
    elif current_mastery <= 0.3:
        print(f"⚠️ 【A3 决策引擎】：[{student_name}] 对该知识点存在严重认知盲区！触发 Tutor Agent 生成补救专项辅导。")
    else:
        print(f"🔄 【A3 决策引擎】：置信度不足，继续推送 2 道强化练习题以确认掌握情况。")

if __name__ == "__main__":
    # 场景 A：渐入佳境的好学生 (偶尔失误一次)
    responses_A = [
        {"is_correct": True},
        {"is_correct": False}, # 可能是粗心失误
        {"is_correct": True},
        {"is_correct": True}
    ]
    simulate_student_journey("学霸小明", initial_prob=0.40, responses=responses_A)
    
    # 场景 B：遇到瓶颈的学生 (连续答错，期间蒙对一题)
    responses_B = [
        {"is_correct": False},
        {"is_correct": False},
        {"is_correct": True},  # 极大概率是蒙对的
        {"is_correct": False}
    ]
    simulate_student_journey("迷茫的小红", initial_prob=0.40, responses=responses_B)
```

### 4. 常见误区与避坑指南
- **误区：** 只要学生做错一道题，就应该将他的掌握度直接清零，并立即让他从头重学一遍知识点。
  - **避坑：** 这种基于硬规则（Hard Rule）的逻辑极其脆弱，极易导致学生的挫败感。真实的人类学习充满波动，学生可能只是点击手滑或粗心算错（Slip）。贝叶斯更新的魅力在于它的“宽容度”，单次的错误只会按比例降低置信度，而不会产生断崖式惩罚，使得 A3 系统的个性化推荐路径显得平滑、自然且具有人情味。

## 实验3：多智能体 (Multi-Agent) 协作流程模拟

### 1. 实验目标
- 体验如何使用基础面向对象编程（OOP）和事件循环来模拟复杂的多智能体（Multi-Agent）系统。
- 剖析在 A3 平台中，不同职能的智能体（如 `Planner`、`Tutor` 和 `Evaluator`）是如何通过“黑板模式（Blackboard）”或直接消息传递来完成一个闭环教育任务的。
- 理解 Agent 之间的“防幻觉与自纠错机制”。

### 2. 实验背景与核心原理
大语言模型（LLM）的注意力是有限的。如果我们将所有复杂的诉求（既要它规划大纲，又要它撰写通俗易懂的教材，还要它自己给教材挑错）全都写进一个巨长的 Prompt 中发给一个独立的 LLM 实例，它极易发生严重的“目标漂移”。
因此，现代 AI 系统的架构范式演进为了**多智能体协作（Multi-Agent Collaboration）**。我们将复杂的任务拆解，实例化出多个不同 `System Prompt` 设定的 Agent，让它们各司其职，甚至互相质询，从而获得超越单个模型的卓越表现。

### 3. 可运行代码示例
本代码出于跨平台演示目的，并不实际发起耗时的 LLM HTTP 请求，而是模拟一组 Agent 在内存中收到消息后的内部流转和仲裁协作机制。

```python
import time

class Agent:
    def __init__(self, name, role):
        self.name = name
        self.role = role

    def process(self, context: dict) -> dict:
        """子类需重写此方法，处理上下文信息并返回更新后的上下文"""
        pass

class TutorAgent(Agent):
    def process(self, context: dict):
        topic = context.get("topic")
        retry_count = context.get("retry_count", 0)
        
        print(f"\n🤖 [{self.name} | {self.role}] 正在深思熟虑生成教学内容...")
        time.sleep(1)
        
        if retry_count == 0:
            # 第一次生成，故意生成一份不太好的材料
            draft = f"关于【{topic}】的讲解：它是 $y = mx+b$ 中损失函数的偏导数连乘。这十分简单。"
        else:
            # 被打回重做后，生成更好的材料
            draft = f"关于【{topic}】的通俗讲解：就像一个蒙着眼睛下山的人，通过试探脚下的坡度（梯度）一步步走向谷底。这非常通俗易懂。"
            
        print(f"   => 生成草稿完毕：\"{draft}\"")
        context["material"] = draft
        return context

class EvaluatorAgent(Agent):
    def process(self, context: dict):
        material = context.get("material", "")
        print(f"\n🕵️ [{self.name} | {self.role}] 正在严苛地评估材料质量...")
        time.sleep(1)
        
        if "通俗易懂" in material:
            context["eval_status"] = "PASSED"
            context["eval_feedback"] = "内容非常生动，比喻恰当，适合新手学生阅读。"
            print("   => 审核结论: ✅ 通过")
        else:
            context["eval_status"] = "FAILED"
            context["eval_feedback"] = "存在专业术语堆砌，缺少直观比喻，晦涩难懂，请重写！"
            print("   => 审核结论: ❌ 不及格，打回重做")
            
        return context

class PlannerAgent:
    def __init__(self):
        self.tutor = TutorAgent("Tutor-Alpha", "内容创作者")
        self.evaluator = EvaluatorAgent("Eval-Omega", "严厉的质量审核员")
        
    def execute_student_request(self, topic: str):
        print(f"======================================================")
        print(f"🌟 [Planner 调度中心] 收到学生请求：我想学习 '{topic}'")
        print(f"======================================================")
        
        # 定义黑板上下文 (Shared Context)
        context = {
            "topic": topic,
            "retry_count": 0,
            "material": "",
            "eval_status": "PENDING"
        }
        
        MAX_RETRIES = 3
        while context["retry_count"] < MAX_RETRIES:
            # 步骤 1：指派 Tutor 生成内容
            context = self.tutor.process(context)
            
            # 步骤 2：指派 Evaluator 进行审核
            context = self.evaluator.process(context)
            
            # 步骤 3：根据反馈仲裁
            if context["eval_status"] == "PASSED":
                print(f"\n🎉 [Planner 调度中心] 协作成功！全链路闭环完成。")
                print(f"📩 最终安全且高质量推送到客户端的内容:\n   {context['material']}")
                break
            else:
                context["retry_count"] += 1
                print(f"\n⚠️ [Planner 调度中心] 协作受阻。错误原因：{context['eval_feedback']}")
                print(f"   => 正在发起第 {context['retry_count']} 次重试流程...")
                
        if context["eval_status"] != "PASSED":
            print(f"\n❌ [Planner 调度中心] 达到最大重试次数，任务强制失败降级。")

if __name__ == "__main__":
    # 初始化总控规划器
    system_planner = PlannerAgent()
    # 模拟实际的学生请求流转过程
    system_planner.execute_student_request("梯度下降算法")
```

### 4. 常见误区与避坑指南
- **误区：** Multi-Agent 系统只是为了让程序看起来很酷，实际上单次模型调用的延迟更低，所以我坚持用一个巨型 Prompt 解决所有问题。
- **避坑：** 这个误区忽略了“大语言模型本质上是概率模型，必然存在随机性与幻觉”。A3 项目引入多智能体的核心目的是**在后台形成“自博弈与自监督（Self-Correction）”**。宁可牺牲几秒钟的后台处理延迟，也必须让负责评估的 Agent 把可能误导学生的虚假知识拦截在给用户展示之前。教育无小事，质量与安全高于一切。

## 实验4：Bloom 认知层级题目分类器

### 1. 实验目标
- 理解布鲁姆认知目标分类学（Bloom's Taxonomy）的 6 个层级：Remember（记忆）、Understand（理解）、Apply（应用）、Analyze（分析）、Evaluate（评价）、Create（创造）。
- 掌握基于“关键词词典 + 动词模式”的轻量级文本分类思路，能够不依赖任何深度学习模型，对一道题目的题干自动判定其所属的 Bloom 层级。
- 学会用 A3 题库中的真实题目作为评估样本，验证分类器的准确率与可解释性。
- 理解这套分类器在 A3 系统中如何支撑“按 Bloom 层级推题”与“学习路径规划”。

### 2. 实验背景与核心原理
在 A3 个性化学习系统里，**Bloom 层级**是个性化推题的核心维度之一：系统需要知道学生当前应该做“记忆型”题目还是“创造型”题目，从而动态调整难度曲线。

人工标注 200+ 道题目的 Bloom 层级非常耗时。本实验基于一个朴素但实用的观察：**不同 Bloom 层级的题干，往往会使用不同类型的动词**：
- Remember 层级的题干常用：**列出 / 什么是 / 写出 / 命名 / 复述**。
- Understand 层级的题干常用：**解释 / 描述 / 总结 / 区分 / 说明**。
- Apply 层级的题干常用：**应用 / 计算 / 使用 / 实现 / 演示**。
- Analyze 层级的题干常用：**分析 / 比较 / 归因 / 区别 / 推断**。
- Evaluate 层级的题干常用：**评估 / 判断 / 批评 / 论证 / 辩护**。
- Create 层级的题干常用：**设计 / 创造 / 构建 / 提出 / 规划**。

我们将用 Python 标准库 `re` 与一个手工维护的关键词词典，扫描题干、统计各层级的动词命中数，取最高得分的层级作为判定结果。

### 3. 可运行代码示例

```python
import re
from collections import Counter

# 1. 关键词词典（每层 5 个常见动词，足够覆盖大多数本科题目）
BLOOM_KEYWORDS = {
    "Remember":  ["什么是", "列出", "写出", "命名", "复述", "定义", "什么是", "指出"],
    "Understand": ["解释", "描述", "总结", "区分", "说明", "归纳", "阐述"],
    "Apply":     ["应用", "计算", "使用", "实现", "演示", "求解", "编写", "运用"],
    "Analyze":   ["分析", "比较", "归因", "区别", "推断", "诊断", "拆解", "分类"],
    "Evaluate":  ["评估", "判断", "批评", "论证", "辩护", "评论", "选择", "权衡"],
    "Create":    ["设计", "创造", "构建", "提出", "规划", "发明", "写出", "综合"]
}

LEVEL_ORDER = ["Remember", "Understand", "Apply", "Analyze", "Evaluate", "Create"]

def classify_bloom(stem: str) -> tuple:
    """
    输入题干字符串,返回 (最可能层级, 置信度, 命中明细)
    """
    scores = Counter()
    hits_detail = {}
    for level, keywords in BLOOM_KEYWORDS.items():
        cnt = 0
        hit_words = []
        for kw in keywords:
            if kw in stem:
                cnt += 1
                hit_words.append(kw)
        scores[level] = cnt
        hits_detail[level] = hit_words

    if not any(scores.values()):
        return ("Understand", 0.0, hits_detail)  # 默认给"理解",作为兜底

    top_level, top_score = scores.most_common(1)[0]
    total = sum(scores.values())
    confidence = round(top_score / total, 2) if total else 0.0
    return (top_level, confidence, hits_detail)


# --- A3 题库中的真实样本测试 ---
TEST_STEMS = [
    ("q-transformer-01", "请列出 Transformer 中 Encoder 和 Decoder 的核心差异。"),
    ("q-rag-02", "请解释 RAG 系统中检索阶段和生成阶段分别解决什么问题。"),
    ("q-cnn-03", "请使用 NumPy 实现一个 3x3 卷积核的边缘检测算子。"),
    ("q-multi_agent-04", "请分析 Planner 和 Tutor Agent 之间的责任边界,并比较其失败模式。"),
    ("q-rl-05", "请评估 Q-learning 和策略梯度在样本效率上的差异,并论证哪种更适合稀疏奖励。"),
    ("q-ai_project-06", "请设计一个可演示的 AI 项目评估方案,覆盖准确率/响应时延/可复现性三个维度。"),
]

print(f"{'ID':25s} {'判定层级':12s} {'置信度':6s}  命中关键词")
print("-" * 80)
for qid, stem in TEST_STEMS:
    level, conf, detail = classify_bloom(stem)
    hits = [w for words in detail.values() for w in words]
    print(f"{qid:25s} {level:12s} {conf:6.2f}  {hits}")
```

### 5. 常见误区与避坑指南
- **误区 1：把"关键词命中数"等同于"层级正确性"。**
  - **避坑：** 关键词命中只能作为“弱信号”。题干里如果同时出现“解释一下 Attention 的计算，并比较 Self-Attention 与 CNN 的差异”，会同时命中 Understand 与 Analyze 两个层级。工程上可采用“取最高分 + 兜底层级”的策略，或改用小模型（如 BERT 微调）做更鲁棒的分类。
- **误区 2：关键词词典越全越好。**
  - **避坑：** 词典太大会带来“过拟合”——一个动词被多个层级收录时反而互相抵消。建议每层控制 5~10 个高频动词，必要时按学科领域拆分词典。
- **误区 3：忽略中文分词对匹配的影响。**
  - **避坑：** 本实验用了字符子串匹配（如 `"解释" in stem`），可以覆盖大多数高频词。若需要支持更细的形态变化（如“解释清楚”/“解释一下”），可改用 `re` 正则模式或 `jieba` 分词。
